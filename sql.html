Days 1–7
Day 1 SELECT, WHERE, ORDER BY Basics Easy ›
-- Table: employees -- emp_id INT, name VARCHAR, dept VARCHAR, salary INT, city VARCHAR, join_date DATE
Problem 1.1
Get all employees from the 'Sales' department, sorted by salary descending.
Use WHERE for filtering, ORDER BY for sorting, DESC for descending.
SELECT *
FROM employees
WHERE dept = 'Sales'
ORDER BY salary DESC;
Key: WHERE filters rows. ORDER BY sorts. DESC = highest first. ASC = lowest first (default).
Problem 1.2
Get the top 5 highest-paid employees. Show only their name and salary.
SELECT specific columns. Use LIMIT (MySQL) or TOP (SQL Server) or FETCH FIRST (PostgreSQL).
SELECT name, salary
FROM employees
ORDER BY salary DESC
LIMIT 5;
Key: Always ORDER BY first, then LIMIT. Without ORDER BY, LIMIT returns arbitrary rows.
Problem 1.3
Get all unique department names from the employees table.
SELECT DISTINCT dept
FROM employees
ORDER BY dept;
Key: DISTINCT removes duplicate values. Essential for exploring categorical columns.
Day 2 WHERE with Multiple Conditions — AND, OR, IN, BETWEEN, LIKE Easy ›
-- Table: orders -- order_id INT, customer_id INT, product VARCHAR, amount DECIMAL, city VARCHAR, order_date DATE, status VARCHAR
Problem 2.1
Find all completed orders where amount is between ₹500 and ₹5000.
SELECT *
FROM orders
WHERE status = 'completed'
  AND amount BETWEEN 500 AND 5000;
Key: BETWEEN is inclusive on both ends. Equivalent to amount >= 500 AND amount <= 5000.
Problem 2.2
Find orders from Mumbai, Delhi, or Bangalore with status NOT 'cancelled'.
SELECT *
FROM orders
WHERE city IN ('Mumbai', 'Delhi', 'Bangalore')
  AND status != 'cancelled';
Key: IN() is cleaner than multiple OR conditions. NOT IN() excludes a list. != and <> both mean "not equal".
Problem 2.3
Find all products whose name starts with 'Phone'.
SELECT *
FROM orders
WHERE product LIKE 'Phone%';
Key: % = any characters. _ = exactly one character. 'Phone%' = starts with Phone. '%Phone%' = contains Phone anywhere.
Day 3 NULL Handling — IS NULL, COALESCE, IFNULL Easy ›
-- Table: customers -- cust_id INT, name VARCHAR, email VARCHAR, phone VARCHAR, referral_code VARCHAR, signup_date DATE
Problem 3.1
Find all customers who have NOT provided their phone number.
SELECT cust_id, name, email
FROM customers
WHERE phone IS NULL;
Key: Never use = NULL. Always IS NULL or IS NOT NULL. NULL means unknown — it can never equal anything, not even itself.
Problem 3.2
Show customer names with their referral code. If no referral code, show 'DIRECT'.
SELECT
  name,
  COALESCE(referral_code, 'DIRECT') AS source
FROM customers;
Key: COALESCE(a, b, c) returns the first non-NULL value. IFNULL(col, default) is MySQL-specific — COALESCE works everywhere.
Problem 3.3
Count how many customers are missing email vs phone (two separate counts in one query).
SELECT
  COUNT(*) - COUNT(email) AS missing_email,
  COUNT(*) - COUNT(phone) AS missing_phone
FROM customers;
Key trick: COUNT(*) counts all rows. COUNT(col) skips NULLs. Their difference = NULL count. This is a very common interview trick.
Day 4 GROUP BY + Aggregate Functions Easy ›
-- Table: sales -- sale_id INT, product_category VARCHAR, product_name VARCHAR, salesperson VARCHAR, region VARCHAR, amount DECIMAL, sale_date DATE
Problem 4.1
Find total sales amount and number of transactions per product category.
SELECT
  product_category,
  COUNT(*) AS total_transactions,
  SUM(amount) AS total_sales,
  ROUND(AVG(amount), 2) AS avg_sale
FROM sales
GROUP BY product_category
ORDER BY total_sales DESC;
Key: Every column in SELECT must either be in GROUP BY or inside an aggregate function. This is a hard SQL rule — violating it causes errors.
Problem 4.2
Find categories with total sales greater than ₹1,00,000.
SELECT
  product_category,
  SUM(amount) AS total_sales
FROM sales
GROUP BY product_category
HAVING SUM(amount) > 100000
ORDER BY total_sales DESC;
Key: HAVING filters after GROUP BY. You cannot use aliases in HAVING — you must repeat the aggregate expression.
Problem 4.3
Find the top salesperson (by total amount) in each region.
This is a two-step problem — first get total per (region, salesperson), then find max per region.
-- Step 1: Get totals per salesperson per region
WITH sp_totals AS (
  SELECT
    region, salesperson,
    SUM(amount) AS total
  FROM sales
  GROUP BY region, salesperson
),
-- Step 2: Find max per region
region_max AS (
  SELECT region, MAX(total) AS max_total
  FROM sp_totals
  GROUP BY region
)
SELECT s.region, s.salesperson, s.total
FROM sp_totals s
JOIN region_max r
  ON s.region = r.region AND s.total = r.max_total
ORDER BY s.region;
Key concept: CTE (WITH clause) breaks complex logic into readable steps. This pattern appears in almost every senior DA interview.
Day 5 String Functions + Date Functions Easy ›
Problem 5.1
From an orders table with order_date, show: month name, year, and monthly revenue for 2023.
SELECT
  MONTHNAME(order_date) AS month_name,
  YEAR(order_date) AS year,
  SUM(amount) AS monthly_revenue
FROM orders
WHERE YEAR(order_date) = 2023
GROUP BY MONTH(order_date), MONTHNAME(order_date), YEAR(order_date)
ORDER BY MONTH(order_date);
Key functions: YEAR(), MONTH(), MONTHNAME(), DAY(), DATEDIFF(), DATE_FORMAT(), NOW(). For PostgreSQL use EXTRACT(MONTH FROM date).
Problem 5.2
From a customers table, extract first name and last name from a full_name column (space-separated).
SELECT
  full_name,
  SUBSTRING_INDEX(full_name, ' ', 1) AS first_name,
  SUBSTRING_INDEX(full_name, ' ', -1) AS last_name
FROM customers;

-- PostgreSQL equivalent:
-- SPLIT_PART(full_name, ' ', 1) AS first_name
-- SPLIT_PART(full_name, ' ', 2) AS last_name
Problem 5.3
Find customers who signed up in the last 30 days.
SELECT *
FROM customers
WHERE signup_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY);

-- PostgreSQL equivalent:
-- WHERE signup_date >= CURRENT_DATE - INTERVAL '30 days'
Day 6 CASE WHEN — Conditional Logic Easy ›
Problem 6.1
Categorise employees into salary bands: Low (<30k), Mid (30k–70k), High (>70k).
SELECT
  name, salary,
  CASE
    WHEN salary < 30000 THEN 'Low'
    WHEN salary BETWEEN 30000 AND 70000 THEN 'Mid'
    ELSE 'High'
  END AS salary_band
FROM employees;
Key: CASE WHEN is SQL's if-else. Evaluated top to bottom — first matching condition wins. ELSE is the default if nothing matches.
Problem 6.2
Count employees in each salary band using CASE WHEN + GROUP BY in one query.
SELECT
  CASE
    WHEN salary < 30000 THEN 'Low'
    WHEN salary BETWEEN 30000 AND 70000 THEN 'Mid'
    ELSE 'High'
  END AS salary_band,
  COUNT(*) AS employee_count
FROM employees
GROUP BY salary_band
ORDER BY employee_count DESC;
Advanced pattern: GROUP BY can reference the alias when the CASE expression is in SELECT — but this depends on the database. Safer to repeat the CASE in GROUP BY.
Day 7 Week 1 Mixed Review — Write 3 queries from scratch Medium ›
Problem 7.1 — No hints
From the orders table: find the city that generated the highest revenue in Q1 (Jan–Mar) of 2024. Show city name and total revenue.
SELECT
  city,
  SUM(amount) AS q1_revenue
FROM orders
WHERE order_date BETWEEN '2024-01-01' AND '2024-03-31'
  AND status != 'cancelled'
GROUP BY city
ORDER BY q1_revenue DESC
LIMIT 1;
Problem 7.2 — No hints
From employees: show each department, number of employees, average salary, and a label "above_avg" or "below_avg" based on whether the dept's average salary is above the company-wide average salary.
SELECT
  dept,
  COUNT(*) AS headcount,
  ROUND(AVG(salary), 0) AS avg_salary,
  CASE
    WHEN AVG(salary) > (SELECT AVG(salary) FROM employees)
    THEN 'above_avg'
    ELSE 'below_avg'
  END AS vs_company
FROM employees
GROUP BY dept
ORDER BY avg_salary DESC;
Key: A scalar subquery (SELECT AVG... inside CASE WHEN) runs once and returns a single value. This is a very common interview pattern.

Days 8–14
Day 8 INNER JOIN and LEFT JOIN Easy ›
-- customers(cust_id, name, city) -- orders(order_id, cust_id, product, amount, order_date, status)
Problem 8.1
Show each order with the customer's name and city.
SELECT
  o.order_id, c.name, c.city,
  o.product, o.amount, o.order_date
FROM orders o
INNER JOIN customers c ON o.cust_id = c.cust_id
ORDER BY o.order_date DESC;
Key: Always alias tables (o, c) when joining. Use o.column notation to avoid ambiguity. INNER JOIN returns only rows with a match in BOTH tables.
Problem 8.2
Find customers who have NEVER placed an order.
Use LEFT JOIN — customers with no orders will have NULL in the orders columns.
SELECT c.cust_id, c.name, c.city
FROM customers c
LEFT JOIN orders o ON c.cust_id = o.cust_id
WHERE o.order_id IS NULL;
Classic pattern: LEFT JOIN + WHERE right table IS NULL = "records in left but not in right". Also achievable with NOT IN or NOT EXISTS subquery.
Problem 8.3
Show total revenue per customer. Include customers with zero orders (show 0).
SELECT
  c.cust_id, c.name,
  COALESCE(SUM(o.amount), 0) AS total_spent
FROM customers c
LEFT JOIN orders o ON c.cust_id = o.cust_id
GROUP BY c.cust_id, c.name
ORDER BY total_spent DESC;
Key: SUM() on NULL returns NULL — COALESCE converts it to 0. This is essential when you LEFT JOIN and aggregate.
Day 9 Multi-Table JOINs (3+ tables) Medium ›
-- orders(order_id, cust_id, product_id, amount, order_date) -- customers(cust_id, name, city, segment) -- products(product_id, product_name, category, cost_price)
Problem 9.1
Show each order with: customer name, product name, category, selling amount, and profit (amount - cost_price).
SELECT
  o.order_id,
  c.name AS customer,
  p.product_name,
  p.category,
  o.amount AS selling_price,
  p.cost_price,
  (o.amount - p.cost_price) AS profit
FROM orders o
JOIN customers c ON o.cust_id = c.cust_id
JOIN products p ON o.product_id = p.product_id
ORDER BY profit DESC;
Key: Chain JOINs one after another. Each JOIN adds a new table. Keep the ON conditions clear — one per JOIN.
Problem 9.2
Find the most profitable product category per customer segment.
WITH segment_category AS (
  SELECT
    c.segment,
    p.category,
    SUM(o.amount - p.cost_price) AS total_profit
  FROM orders o
  JOIN customers c ON o.cust_id = c.cust_id
  JOIN products p ON o.product_id = p.product_id
  GROUP BY c.segment, p.category
),
ranked AS (
  SELECT *,
    RANK() OVER (PARTITION BY segment ORDER BY total_profit DESC) AS rnk
  FROM segment_category
)
SELECT segment, category, total_profit
FROM ranked
WHERE rnk = 1;
Key pattern: CTE → aggregation → Window RANK → filter rank=1. This exact pattern comes up in almost every product company SQL interview.
Day 10 Subqueries — IN, EXISTS, Correlated, Scalar Medium ›
Problem 10.1
Find employees who earn more than the average salary of their own department.
This needs a correlated subquery — the inner query references the outer query's row.
SELECT e1.name, e1.dept, e1.salary
FROM employees e1
WHERE e1.salary > (
  SELECT AVG(e2.salary)
  FROM employees e2
  WHERE e2.dept = e1.dept   -- correlated: references outer query
)
ORDER BY e1.dept, e1.salary DESC;
Correlated subquery runs once per outer row. Slow on huge tables — window functions are faster but correlated subqueries show deep SQL understanding.
Problem 10.2
Find products that have never been ordered.
-- Method 1: NOT IN subquery
SELECT * FROM products
WHERE product_id NOT IN (
  SELECT DISTINCT product_id FROM orders
);

-- Method 2: NOT EXISTS (safer with NULLs)
SELECT * FROM products p
WHERE NOT EXISTS (
  SELECT 1 FROM orders o
  WHERE o.product_id = p.product_id
);
Important: NOT IN fails silently if the subquery returns any NULL values. NOT EXISTS is safer and often faster. Know both — interviewers may specifically ask which is better.
Days 11–14 CTEs, Self JOINs, UNION, and Pivot-style Queries Medium ›
Problem 11 — Self JOIN
From an employees table with a manager_id column, show each employee with their manager's name.
SELECT
  e.name AS employee,
  m.name AS manager
FROM employees e
LEFT JOIN employees m ON e.manager_id = m.emp_id;
Self JOIN: Joining a table to itself using different aliases. LEFT JOIN ensures employees with no manager (top level) still appear — with NULL as manager.
Problem 12 — Pivot with CASE WHEN
Show monthly sales pivot: one row per product_category, columns for Jan, Feb, Mar totals.
SELECT
  product_category,
  SUM(CASE WHEN MONTH(sale_date) = 1 THEN amount ELSE 0 END) AS jan,
  SUM(CASE WHEN MONTH(sale_date) = 2 THEN amount ELSE 0 END) AS feb,
  SUM(CASE WHEN MONTH(sale_date) = 3 THEN amount ELSE 0 END) AS mar
FROM sales
WHERE YEAR(sale_date) = 2024
GROUP BY product_category;
Manual pivot: No PIVOT keyword in standard SQL — use SUM(CASE WHEN ...) pattern. Very common in reporting queries and interview tasks.
Problem 13 — Running Total with CTE
Show daily revenue with a running total for Jan 2024.
WITH daily AS (
  SELECT
    DATE(order_date) AS day,
    SUM(amount) AS daily_rev
  FROM orders
  WHERE order_date BETWEEN '2024-01-01' AND '2024-01-31'
  GROUP BY DATE(order_date)
)
SELECT
  day, daily_rev,
  SUM(daily_rev) OVER (ORDER BY day) AS running_total
FROM daily
ORDER BY day;

Days 15–21
Day 15 ROW_NUMBER, RANK, DENSE_RANK — Know the difference Medium ›
Problem 15.1 — The Classic
Find the top 3 employees by salary in each department.
WITH ranked AS (
  SELECT
    name, dept, salary,
    DENSE_RANK() OVER (
      PARTITION BY dept
      ORDER BY salary DESC
    ) AS rnk
  FROM employees
)
SELECT name, dept, salary, rnk
FROM ranked
WHERE rnk <= 3;
ROW_NUMBER — unique rank (1,2,3,4 — no ties)
RANK — ties get same rank, next rank skips (1,2,2,4)
DENSE_RANK — ties get same rank, no skip (1,2,2,3) ← usually the right choice for "top N" problems
Problem 15.2
Deduplicate a table — keep only the most recent order per customer.
WITH ranked AS (
  SELECT *,
    ROW_NUMBER() OVER (
      PARTITION BY cust_id
      ORDER BY order_date DESC
    ) AS rn
  FROM orders
)
SELECT * FROM ranked WHERE rn = 1;
ROW_NUMBER for deduplication is one of the most important patterns. Use ROW_NUMBER (not RANK) here so each row gets a unique number — only one row per customer will be rn=1.
Day 16–17 LAG and LEAD — Month-over-Month, Day-over-Day comparisons Medium ›
Problem 16.1
Show monthly revenue with previous month's revenue and the % change (MoM growth).
WITH monthly AS (
  SELECT
    DATE_FORMAT(order_date, '%Y-%m') AS month,
    SUM(amount) AS revenue
  FROM orders
  GROUP BY 1
)
SELECT
  month, revenue,
  LAG(revenue) OVER (ORDER BY month) AS prev_month,
  ROUND(
    (revenue - LAG(revenue) OVER (ORDER BY month))
    * 100.0
    / NULLIF(LAG(revenue) OVER (ORDER BY month), 0),
  2) AS mom_pct
FROM monthly
ORDER BY month;
LAG(col, n) = value n rows behind. LEAD(col, n) = value n rows ahead. NULLIF prevents divide-by-zero error. MoM% formula = (current - previous) / previous × 100.
Problem 17.1
Find all months where revenue DECREASED compared to the previous month.
WITH monthly AS (
  SELECT
    DATE_FORMAT(order_date, '%Y-%m') AS month,
    SUM(amount) AS revenue
  FROM orders GROUP BY 1
),
with_lag AS (
  SELECT month, revenue,
    LAG(revenue) OVER (ORDER BY month) AS prev
  FROM monthly
)
SELECT month, revenue, prev,
  revenue - prev AS change
FROM with_lag
WHERE revenue < prev;
Day 18–21 SUM/AVG OVER (Running totals, Moving averages, Percentile) Hard ›
Problem 18
Calculate a 3-day moving average of daily sales.
WITH daily AS (
  SELECT DATE(order_date) AS day, SUM(amount) AS rev
  FROM orders GROUP BY 1
)
SELECT
  day, rev,
  AVG(rev) OVER (
    ORDER BY day
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
  ) AS moving_avg_3d
FROM daily;
ROWS BETWEEN defines the window frame. "2 PRECEDING AND CURRENT ROW" = current row + 2 rows before it = 3-day window. Used heavily in trend analysis.
Problem 19 — Percentile
Find which percentile each employee's salary falls in.
SELECT
  name, salary,
  ROUND(
    PERCENT_RANK() OVER (ORDER BY salary) * 100, 1
  ) AS percentile
FROM employees;
Problem 20–21 — Hard combo
For each customer, show: total orders, first order date, last order date, days since last order, and classify them as 'Active' (last order within 30 days), 'At Risk' (31–90 days), or 'Churned' (>90 days).
SELECT
  cust_id,
  COUNT(*) AS total_orders,
  MIN(order_date) AS first_order,
  MAX(order_date) AS last_order,
  DATEDIFF(CURDATE(), MAX(order_date)) AS days_since,
  CASE
    WHEN DATEDIFF(CURDATE(), MAX(order_date)) <= 30
      THEN 'Active'
    WHEN DATEDIFF(CURDATE(), MAX(order_date)) <= 90
      THEN 'At Risk'
    ELSE 'Churned'
  END AS customer_status
FROM orders
GROUP BY cust_id
ORDER BY days_since;
This exact query pattern is used in real product companies to build customer health dashboards. Combines GROUP BY, date functions, and CASE WHEN — shows real analytical thinking.

Day 22 Duplicate Detection and Data Quality Queries Medium ›
Problem 22.1
Find duplicate orders — same customer_id, product, and amount on the same date.
SELECT
  cust_id, product, amount, order_date,
  COUNT(*) AS duplicate_count
FROM orders
GROUP BY cust_id, product, amount, order_date
HAVING COUNT(*) > 1;
Problem 22.2
Delete duplicate rows, keeping only the one with the lowest order_id.
DELETE FROM orders
WHERE order_id NOT IN (
  SELECT MIN(order_id)
  FROM orders
  GROUP BY cust_id, product, amount, order_date
);
Classic dedup pattern: Keep the MIN(id) from each group of duplicates. The NOT IN subquery identifies which ids to delete.
Day 23–24 Retention Analysis — New vs Returning Customers Hard ›
Problem 23
For each month, count: new customers (first order ever that month) vs returning customers.
WITH first_orders AS (
  SELECT
    cust_id,
    MIN(order_date) AS first_order_date
  FROM orders
  GROUP BY cust_id
),
monthly_orders AS (
  SELECT
    o.cust_id,
    DATE_FORMAT(o.order_date, '%Y-%m') AS month,
    CASE
      WHEN DATE_FORMAT(f.first_order_date, '%Y-%m')
         = DATE_FORMAT(o.order_date, '%Y-%m')
      THEN 'new'
      ELSE 'returning'
    END AS customer_type
  FROM orders o
  JOIN first_orders f ON o.cust_id = f.cust_id
)
SELECT
  month,
  COUNT(DISTINCT CASE WHEN customer_type = 'new' THEN cust_id END) AS new_customers,
  COUNT(DISTINCT CASE WHEN customer_type = 'returning' THEN cust_id END) AS returning_customers
FROM monthly_orders
GROUP BY month
ORDER BY month;
This is a real product analyst query. The key insight: find each customer's first order month, then label every order as "new" or "returning" based on whether it matches their first month.
Day 25–26 Cohort Analysis — Month-1 Retention Hard ›
Problem 25
Build a cohort retention table: for customers who first ordered in each month (cohort), what % came back in the following month?
WITH cohorts AS (
  SELECT
    cust_id,
    DATE_FORMAT(MIN(order_date), '%Y-%m') AS cohort_month
  FROM orders
  GROUP BY cust_id
),
activity AS (
  SELECT
    o.cust_id,
    c.cohort_month,
    DATE_FORMAT(o.order_date, '%Y-%m') AS active_month,
    PERIOD_DIFF(
      DATE_FORMAT(o.order_date, '%Y%m'),
      DATE_FORMAT(STR_TO_DATE(c.cohort_month, '%Y-%m'), '%Y%m')
    ) AS months_since_join
  FROM orders o
  JOIN cohorts c ON o.cust_id = c.cust_id
)
SELECT
  cohort_month,
  COUNT(DISTINCT cust_id) AS cohort_size,
  COUNT(DISTINCT CASE WHEN months_since_join = 0 THEN cust_id END) AS m0,
  COUNT(DISTINCT CASE WHEN months_since_join = 1 THEN cust_id END) AS m1_retained,
  ROUND(
    COUNT(DISTINCT CASE WHEN months_since_join = 1 THEN cust_id END) * 100.0
    / COUNT(DISTINCT CASE WHEN months_since_join = 0 THEN cust_id END), 1
  ) AS m1_retention_pct
FROM activity
GROUP BY cohort_month
ORDER BY cohort_month;
Cohort analysis is a hallmark of product analyst roles. Understanding this query fully — and being able to explain what cohort_month and months_since_join mean — will impress any interviewer.
Days 27–30 Final Exam — 4 Unsolved Problems (write solutions yourself) Hard ›
Final 1
From an orders table: find the second-highest revenue-generating customer. If there's a tie, show all tied customers.
WITH totals AS (
  SELECT cust_id, SUM(amount) AS total
  FROM orders GROUP BY cust_id
),
ranked AS (
  SELECT *, DENSE_RANK() OVER (ORDER BY total DESC) AS rnk
  FROM totals
)
SELECT cust_id, total FROM ranked WHERE rnk = 2;
Final 2
Find customers who ordered in Jan 2024 but NOT in Feb 2024.
SELECT DISTINCT cust_id
FROM orders
WHERE order_date BETWEEN '2024-01-01' AND '2024-01-31'

AND cust_id NOT IN (
  SELECT DISTINCT cust_id FROM orders
  WHERE order_date BETWEEN '2024-02-01' AND '2024-02-29'
);
Final 3
Calculate 30-day rolling revenue for each day in 2024.
WITH daily AS (
  SELECT DATE(order_date) AS day, SUM(amount) AS rev
  FROM orders WHERE YEAR(order_date) = 2024
  GROUP BY DATE(order_date)
)
SELECT
  day, rev,
  SUM(rev) OVER (
    ORDER BY day
    ROWS BETWEEN 29 PRECEDING AND CURRENT ROW
  ) AS rolling_30d
FROM daily;
Final 4 — The Hardest
Identify "power users" — customers who are in the top 20% by order count AND top 20% by total spend.
WITH customer_stats AS (
  SELECT
    cust_id,
    COUNT(*) AS order_count,
    SUM(amount) AS total_spend
  FROM orders
  GROUP BY cust_id
),
percentiles AS (
  SELECT *,
    PERCENT_RANK() OVER (ORDER BY order_count) AS order_pct,
    PERCENT_RANK() OVER (ORDER BY total_spend) AS spend_pct
  FROM customer_stats
)
SELECT cust_id, order_count, total_spend
FROM percentiles
WHERE order_pct >= 0.8 AND spend_pct >= 0.8
ORDER BY total_spend DESC;
This combines: aggregation + window functions + PERCENT_RANK + multiple filters. If he can explain and write this, he's ready for senior data analyst SQL rounds.
