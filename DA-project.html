Phase 1 — Dataset & Setup
Get the data, understand its structure, set up your tools. This is Day 1 of every real analyst job.
1.1 Where to get the dataset (free, real data) ›
Use the Brazilian E-Commerce (Olist) dataset from Kaggle. It's a real dataset from a Brazilian e-commerce company with 100,000 orders, multiple tables — perfect for a portfolio project.

Download link: kaggle.com/datasets/olistbr/brazilian-ecommerce

It comes with 9 CSV files that form a proper relational database:
FileWhat it containsKey Columns
olist_orders_dataset.csvAll ordersorder_id, customer_id, status, purchase_timestamp
olist_order_items_dataset.csvItems in each orderorder_id, product_id, price, freight_value
olist_customers_dataset.csvCustomer detailscustomer_id, city, state
olist_products_dataset.csvProduct detailsproduct_id, product_category_name
olist_order_reviews_dataset.csvCustomer reviewsorder_id, review_score
olist_sellers_dataset.csvSeller detailsseller_id, city, state
Why this dataset? It has real messy data — NULLs, delivery delays, multiple statuses, date/time fields. Interviewers are impressed when you use a real dataset instead of a clean tutorial toy dataset.

1.3 Define your 5 Business Questions before touching the data ›
This is the most important step and most analysts skip it. Before writing a single query, define what business questions you'll answer. This makes your project look like real analytical work, not random data exploration.

Write these in your project README / Confluence / Notion:
Your 5 Business Questions
1. What is the monthly revenue trend — is the business growing?
2. Which product categories drive the most revenue and profit?
3. How does delivery performance vary by state? Are there problem regions?
4. What is the customer retention rate — do customers come back?
5. What's the relationship between delivery delay and review score?
Interview tip: When presenting your project, always start with "I defined 5 business questions first..." — it immediately shows you think like an analyst, not just a SQL coder.
Phase 2 — Data Cleaning
Real data is always dirty. Document every issue you find and how you fixed it. This section is what separates junior candidates from good ones.
2.1 Initial data exploration — run these queries first SQL ›
Run these exploration queries on every table before any cleaning:
-- 1. Row counts for all tables
SELECT 'orders' AS tbl, COUNT(*) AS rows FROM olist_orders
UNION ALL SELECT 'items', COUNT(*) FROM olist_order_items
UNION ALL SELECT 'customers', COUNT(*) FROM olist_customers
UNION ALL SELECT 'products', COUNT(*) FROM olist_products;

-- 2. Check NULLs in orders table
SELECT
  COUNT(*) - COUNT(order_id) AS null_order_id,
  COUNT(*) - COUNT(customer_id) AS null_customer,
  COUNT(*) - COUNT(order_status) AS null_status,
  COUNT(*) - COUNT(order_delivered_customer_date) AS null_delivery
FROM olist_orders;

-- 3. Unique order statuses
SELECT order_status, COUNT(*) AS count
FROM olist_orders
GROUP BY order_status
ORDER BY count DESC;

-- 4. Check date ranges
SELECT
  MIN(order_purchase_timestamp) AS earliest,
  MAX(order_purchase_timestamp) AS latest
FROM olist_orders;
Document what you find. Write a short "Data Quality Issues Found" section in your project notes. Example: "17% of orders have NULL delivery dates — these are orders that were cancelled or not yet delivered. I excluded them from delivery analysis."
2.2 Common issues in this dataset and how to handle them SQL ›
Issue 1 — Orders with no delivery date: ~3,000 orders have NULL delivery date. These are cancelled/in-transit. Keep them for revenue analysis but exclude from delivery time analysis.
-- For delivery analysis, always filter
WHERE order_status = 'delivered'
  AND order_delivered_customer_date IS NOT NULL
Issue 2 — Delivery was before estimated: Some orders show delivery AFTER the estimated date — these are late deliveries. Calculate this as a new column.
SELECT
  order_id,
  DATEDIFF(order_delivered_customer_date,
            order_estimated_delivery_date) AS delay_days,
  CASE
    WHEN order_delivered_customer_date <= order_estimated_delivery_date
    THEN 'On Time'
    ELSE 'Late'
  END AS delivery_status
FROM olist_orders
WHERE order_status = 'delivered';
Issue 3 — Product category names in Portuguese: The dataset has category names in Portuguese. You can join with the category_name_translation table or use CASE WHEN to translate the top 10.
-- Join the translation table provided in the dataset
SELECT p.product_category_name,
       t.product_category_name_english
FROM olist_products p
LEFT JOIN product_category_name_translation t
  ON p.product_category_name = t.product_category_name;
2.3 Create a clean master view / staging table SQL ›
Join all tables into one clean view that you'll use for all analysis. This is standard practice in real jobs.
CREATE VIEW vw_orders_master AS
SELECT
  o.order_id,
  o.order_status,
  o.order_purchase_timestamp,
  DATE(o.order_purchase_timestamp) AS order_date,
  DATE_FORMAT(o.order_purchase_timestamp, '%Y-%m') AS order_month,
  o.order_delivered_customer_date,
  o.order_estimated_delivery_date,
  DATEDIFF(o.order_delivered_customer_date,
            o.order_estimated_delivery_date) AS delivery_delay_days,
  c.customer_id,
  c.customer_city,
  c.customer_state,
  i.product_id,
  i.price,
  i.freight_value,
  (i.price + i.freight_value) AS total_order_value,
  t.product_category_name_english AS category,
  r.review_score
FROM olist_orders o
JOIN olist_customers c ON o.customer_id = c.customer_id
JOIN olist_order_items i ON o.order_id = i.order_id
LEFT JOIN olist_products p ON i.product_id = p.product_id
LEFT JOIN product_category_name_translation t
  ON p.product_category_name = t.product_category_name
LEFT JOIN olist_order_reviews r ON o.order_id = r.order_id;
Now all your analysis queries can use: FROM vw_orders_master instead of repeating all the JOINs every time. Clean and maintainable.
Phase 3 — SQL Analysis
Answer your 5 business questions with SQL. Write clean, commented queries — save them in a .sql file for your portfolio.
Q1 Monthly Revenue Trend — Is the business growing? SQL › 
-- Q1: Monthly Revenue with MoM Growth %
WITH monthly_rev AS (
  SELECT
    order_month,
    SUM(total_order_value) AS revenue,
    COUNT(DISTINCT order_id) AS total_orders
  FROM vw_orders_master
  WHERE order_status = 'delivered'
  GROUP BY order_month
)
SELECT
  order_month,
  ROUND(revenue, 2) AS revenue,
  total_orders,
  LAG(revenue) OVER (ORDER BY order_month) AS prev_month_rev,
  ROUND(
    (revenue - LAG(revenue) OVER (ORDER BY order_month))
    * 100.0
    / NULLIF(LAG(revenue) OVER (ORDER BY order_month), 0),
  1) AS mom_growth_pct
FROM monthly_rev
ORDER BY order_month;
Expected insight: The Olist data shows strong growth through 2017-2018 with a seasonal spike in November (Black Friday). Call this out in your presentation.
Q2 Top Product Categories by Revenue SQL › 
-- Q2: Revenue, Orders, and Avg Value per Category (Top 15)
SELECT
  COALESCE(category, 'Uncategorized') AS category,
  COUNT(DISTINCT order_id) AS total_orders,
  ROUND(SUM(total_order_value), 2) AS total_revenue,
  ROUND(AVG(total_order_value), 2) AS avg_order_value,
  ROUND(AVG(review_score), 2) AS avg_review
FROM vw_orders_master
WHERE order_status = 'delivered'
GROUP BY category
ORDER BY total_revenue DESC
LIMIT 15;
Q3 Delivery Performance by State SQL › 
-- Q3: Delivery performance per state
SELECT
  customer_state,
  COUNT(*) AS total_deliveries,
  ROUND(AVG(delivery_delay_days), 1) AS avg_delay_days,
  SUM(CASE WHEN delivery_delay_days > 0 THEN 1 ELSE 0 END) AS late_orders,
  ROUND(
    SUM(CASE WHEN delivery_delay_days > 0 THEN 1 ELSE 0 END) * 100.0
    / COUNT(*), 1
  ) AS late_pct
FROM vw_orders_master
WHERE order_status = 'delivered'
  AND delivery_delay_days IS NOT NULL
GROUP BY customer_state
ORDER BY late_pct DESC;
Expected insight: Northern states (AM, RR, AP) have significantly higher late delivery rates due to remote geography. SP (São Paulo) has the best delivery performance. This is a geographic logistics insight — great for a dashboard map.
Q4 Customer Retention — Do buyers come back? SQL › 
-- Q4: Customer order frequency breakdown
WITH customer_orders AS (
  SELECT
    customer_id,
    COUNT(DISTINCT order_id) AS order_count
  FROM vw_orders_master
  GROUP BY customer_id
)
SELECT
  CASE
    WHEN order_count = 1 THEN 'One-time buyer'
    WHEN order_count BETWEEN 2 AND 3 THEN 'Occasional (2-3 orders)'
    WHEN order_count BETWEEN 4 AND 6 THEN 'Regular (4-6 orders)'
    ELSE 'Loyal (7+ orders)'
  END AS customer_segment,
  COUNT(*) AS customer_count,
  ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS pct_of_total
FROM customer_orders
GROUP BY customer_segment
ORDER BY customer_count DESC;
Expected insight: ~97% of Olist customers are one-time buyers — extremely low retention. This is actually the most important business insight in the dataset and a great discussion point. "The business has an acquisition problem solved but a retention problem unsolved."
Q5 Delivery Delay vs Review Score Correlation SQL › 
-- Q5: Does late delivery hurt review scores?
SELECT
  CASE
    WHEN delivery_delay_days < 0  THEN 'Early delivery'
    WHEN delivery_delay_days = 0  THEN 'On time'
    WHEN delivery_delay_days <= 7  THEN '1-7 days late'
    WHEN delivery_delay_days <= 14 THEN '8-14 days late'
    ELSE '15+ days late'
  END AS delivery_category,
  COUNT(*) AS order_count,
  ROUND(AVG(review_score), 2) AS avg_review,
  SUM(CASE WHEN review_score >= 4 THEN 1 ELSE 0 END) AS positive_reviews,
  SUM(CASE WHEN review_score <= 2 THEN 1 ELSE 0 END) AS negative_reviews
FROM vw_orders_master
WHERE order_status = 'delivered'
  AND delivery_delay_days IS NOT NULL
  AND review_score IS NOT NULL
GROUP BY delivery_category
ORDER BY AVG(review_score) DESC;
Expected insight: Early deliveries average 4.3+ stars. Orders 15+ days late average below 2.5 stars. Clear correlation — and you can show it visually in the dashboard as a bar chart. This is the kind of insight that drives real business decisions.
Phase 4 — Build the Dashboard
Turn your SQL results into a 1-page interactive dashboard in Power BI or Tableau. This is what the interviewer will actually see.
4.1 Connect Power BI to your MySQL database Power BI ›
In Power BI Desktop:
1. Home → Get Data → MySQL database
2. Enter: Server = localhost, Database = olist_ecommerce
3. Select your tables OR import the view vw_orders_master directly
4. In Power Query, apply any final transformations (rename columns, change types)

Alternative — Import from CSV:
Export your SQL query results as CSVs and import those. Faster for a portfolio project.
Pro tip: Import your 5 analysis query results as separate tables in Power BI — one per business question. Name them clearly: monthly_revenue, category_performance, etc.

4.3 3 DAX measures to add to your dashboard DAX ›
Add these DAX measures — they show you know Power BI beyond drag-and-drop:
Total Revenue = SUM(orders_master[total_order_value])

Late Delivery % = 
  DIVIDE(
    COUNTROWS(FILTER(orders_master, orders_master[delivery_delay_days] > 0)),
    COUNTROWS(orders_master),
    0
  ) * 100

Avg Review Score = AVERAGE(orders_master[review_score])
Phase 5 — Insights, Story & Presentation
The most important phase. The insights YOU surface and how you communicate them is what gets you hired.
5.1 The 5 Key Insights to present (what the data actually shows) Insight ›
Insight 1 — Revenue Growth
"Olist grew revenue 3x from 2017 to 2018, with a November 2017 spike of 47% MoM — clearly driven by Black Friday. Q3 2018 shows a plateau, which warrants investigation."
Insight 2 — Category Concentration Risk
"Top 5 categories (bed/bath, electronics, sports, furniture, computing) contribute ~60% of revenue. High concentration in any 1–2 categories is a business risk if they face competition or regulation."
Insight 3 — Delivery is a Northern Problem
"States in northern Brazil (AM, RR, PA) have 3–4x higher late delivery rates than Southeast states. Logistics investment in these regions could directly improve satisfaction scores."
Insight 4 — Retention Crisis
"97% of customers made only 1 purchase. This is the single biggest growth lever — improving retention from 3% to even 8% could potentially double long-term revenue without acquiring new customers."
Insight 5 — Delay Kills Satisfaction
"Orders delivered 15+ days late score an average of 2.4/5 stars vs 4.4/5 for early deliveries. Each week of delay correlates with a ~0.5 star drop. Improving logistics directly improves NPS."
5.2 How to present this project in an interview (exact script) Presentation ›
Opening (30 seconds):
"I did an end-to-end analysis on the Olist Brazilian e-commerce dataset — about 100,000 real orders. I started by defining 5 business questions, then cleaned the data, wrote SQL queries to answer each question, and built a Power BI dashboard to visualise the findings."

Data cleaning highlight (30 seconds):
"The data had real quality issues — about 17% of orders had NULL delivery dates because they were cancelled. The product names were in Portuguese, so I joined a translation table. I documented all issues and built a master view in SQL so my analysis queries were clean."

Key insight (60 seconds):
"The most important finding was the retention rate — 97% of customers never ordered again. Combined with the fact that late delivery correlated directly with low review scores, my recommendation was: Olist should prioritise logistics improvement in northern states, because fixing delivery times would simultaneously improve reviews, word-of-mouth, and repeat purchase probability."

Close:
"The dashboard has slicers for year, state, and category so the product and logistics teams can explore their specific areas."
Key principle: End with a recommendation tied to a business outcome, not just a chart description. "Late deliveries cause low reviews" → "Therefore, fix logistics in these 5 states first, targeting a 15% reduction in late delivery rate."
